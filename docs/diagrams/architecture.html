One deployment, many companies

What exists today: a mobile-first PWA, a NestJS API behind a guard chain, and one Postgres database whose every business query is scoped to the company on the session cookie.

The centrepiece

One deployment, many companies

  • companyId is read from the session cookie by the JWT guard — never from the body, query or URL
  • Every business query filters by it, so a new company is a row, not a deploy
  • Enforced in NestJS, not in Postgres row-level security; Supabase is used only as the database host

Across the boundary

Browser → server

  • The shell is static files from nginx; the API is a separate origin, so the CSP has to name it (connect-src)
  • The session cookie is httpOnly + SameSite=Lax, so WEB_ORIGIN must match where the app is served
  • The service worker precaches the shell, so the app opens with no network
